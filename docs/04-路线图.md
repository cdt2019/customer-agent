## 总览

```mermaid
flowchart LR
  P0[0 准备和实测] --> P1[1 主干跑通]
  P1 --> P2[2 后台和检索调优]
  P2 --> P3[3 对话服务]
  P3 --> P4[4 模拟站和聊天窗]
  P4 --> P5[5 运营和上线准备]
  P5 -.-> P6[6 接入真实店铺]
```

| 期 | 目标 | 粗估 |
|---|---|---|
| 0 | 把「估计」换成实测数字 | 2–3 天 |
| 1 | 命令行里问一句，能带出处回答，能出基线分数 | 3–5 天 |
| 2 | 导入、切块、测试台、评测的后台可用，量出每一步值多少分，定下模型和链路 | 2–3 周 |
| 3 | 多轮对话、工具、转人工，走 HTTP 接口 | 1 周 |
| 4 | 模拟店铺里完整聊一遍售前和售后 | 1 周 |
| 5 | 会话记录、花费、防滥用、部署 | 1 周 |
| 6 | 接入真实店铺 | 视接入方而定 |

第 1 期之前不做界面。第 2 期先做后台，是因为调优时每天都要看检索过程。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 第一个接入方的内容太少，看不出各步差别 | 研究价值打折 | 同时用更大的练习语料 |
| 老显卡装不上或太慢 | 第 0 期卡住 | 退到处理器或在线接口 |
| 磁盘空间不够 | 模型放不下 | 下载前查空间，用不上的模型及时删 |
| 调优没有尽头 | 拖慢后面 | 第 2 期达到分数线就停 |
| 评测题太少或出得偏 | 分数不可信 | 上线后把真实问题补进来 |
| 模型花费超预期 | 运营成本 | 第 3 期实测，设每日上限 |
