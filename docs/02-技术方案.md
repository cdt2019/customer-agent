## 0. 实现约束：用模拟站代替接入方

（2026-11-22 定）实现阶段不改真实接入方的任何代码，接入方用本仓库里自己做的模拟站代替。下文凡是和这一节冲突的，以这一节为准。

**模拟站（`demo/`）有两部分：**

| 部分 | 是什么 | 代替接入方的什么 |
|---|---|---|
| 模拟店铺后端 | 一个很小的服务，提供 §5.2 那组接口，数据是一批写好的样例 | 帮助文章、商品、订单、工单、客服设置；签发访客令牌；转发对话 |
| 模拟店铺网页 | 几个简单页面：首页、商品页、订单页、帮助页，带聊天窗 | 接入方的店铺前台 |

- **样例数据**：帮助文章和商品介绍参照第一个接入方整理了一份；订单和工单是编的，覆盖各种状态（待付款、已交付、质保内、质保外、有在办工单）。
- **切换身份**：模拟网页上能切换「游客 / 会员甲 / 会员乙」，用来验证只能看到自己的订单。
- **聊天窗做在本仓库**（`widget/`），是一个能嵌进任意网页的独立组件，悬浮窗和整页版都有。模拟网页嵌的就是它。
- **§5.2 的接口先由模拟后端实现**，接口的样子就按这里定。以后接真实接入方时，接入方照这份接口实现，客服服务不用改。
- **接真实接入方**（专用接口、把聊天窗放进前台、建真工单）是最后单独的一期。

这样做的额外好处：一个新接入方怎么接，在模拟站上就先走通了一遍。

## 1. 选型

### 1.1 客服服务（Python）

| 项 | 选 | 依据 |
|---|---|---|
| 语言和环境 | Python 3.12，uv 管理；`torch 2.14.1` 钉在 cu126 源 | 向量模型、重排、评测工具以 Python 为主。这是最后支持本机显卡的 PyTorch，已实测可用 |
| 写法 | 自己拼主干，不用 LlamaIndex、LangChain 这类库做骨架 | 目的是看清每一步；调研时这些库的重心已转向别处，不是必需 |
| 网页接口 | FastAPI，回答用 SSE 按字返回 | 自动生成接口文档，后台前端的类型从它生成 |
| 数据库 | PostgreSQL，SQLAlchemy 2 + Alembic 管表结构 | 本机和线上都已有 PostgreSQL |
| 向量库 | Qdrant | 本机用 Windows 版程序，线上用容器 |
| 向量模型 | bge-m3 或 Qwen3-Embedding-0.6B，评测后定 | 都支持中文、能在 4GB 显卡上跑；差距用自己的题比（§11） |
| 重排模型 | bge-reranker-v2-m3，只在本机评测里用 | 处理器上太慢，线上不开（§11） |
| 文档解析 | 自带解析器（Markdown、TXT、HTML）+ Docling（Word、PDF），包一层可替换；MinerU 以后作为单独服务接入 | Docling 的中文效果和本机速度「待实测」；MinerU 对本机偏重，许可未核实 |
| 回答的模型 | 先用 DeepSeek。接兼容 OpenAI 的接口，供应商、型号、密钥都在环境变量里 | 这一层只有一个 `complete(系统提示, 用户消息)`，换供应商不动别的代码 |
| 评测 | 检索分数自己算（命中率、MRR）；回答质量用模型打分，Ragas 作参考 | 调研：Ragas 0.4 系列在改接口，容易踩坑，先自己算 |

### 1.2 管理后台（网页）


| 项 | 选 |
|---|---|
| 构建 | Vite 单页应用（不用 TanStack Start：后台不需要服务端渲染） |
| 路由和数据 | TanStack Router、TanStack Query |
| 表格 | TanStack Table |
| 组件 | shadcn 的 Base UI 版（风格 `base-nova`），用 CLI 添加 |
| 样式 | Tailwind CSS 4，颜色只放在令牌文件里 |
| 表单 | react-hook-form + zod |
| 图标、提示、图表 | lucide、sonner、shadcn 的 chart（recharts） |
| 接口类型 | 从 FastAPI 生成的 OpenAPI 用 openapi-typescript 生成，不手写 |

后台自己初始化一份 shadcn 组件和令牌，不依赖接入方的组件库。前端的规矩（组件一个来源、不写死颜色、页面里不写原生交互元素）见[界面设计规范](03-界面设计规范.md) §6。

### 1.3 聊天窗

做在本仓库的 `widget/`（见 §0）：React + Tailwind 4，打包成一个脚本文件（约 81KB gzip），样式内联，挂在 Shadow DOM 里，和宿主页面互不影响。没用 shadcn：它的弹层渲染到 Shadow DOM 外面。尺寸全用 px，因为 rem 跟着宿主页面的根字号走。Tailwind 4 的 `@property` 在 Shadow DOM 里不生效，挂载时把这几条规则放到宿主页面上（只注册变量）。接真实接入方时，是直接嵌这个组件还是用接入方自己的组件库重做一遍，接入时再定。

## 2. 整体结构

```
买家浏览器
   │  只连接入方的域名
   ▼
接入方后端 ───────转发对话，附访客令牌──► 客服服务（Python）
   ▲                                       │
   │◄──── 查商品、查订单、建工单 ────────────┤
                                           ├──► 回答的模型（兼容 OpenAI 接口，默认 DeepSeek）
                                           ├──► Qdrant（向量）
                                           └──► PostgreSQL（单独一个库）
管理后台（Vite 单页应用）──────────────────► 客服服务
```

- 客服服务不对公网开放，只有接入方后端和管理后台能连。
- 客服服务不连接入方的数据库。
- 客服服务挂了，接入方的转发接口返回「暂不可用」，聊天窗显示联系方式。

## 3. 目录结构

各目录和模块做什么，见仓库根目录 [CLAUDE.md](../CLAUDE.md) 的「目录」一节（随代码一起更新）。

## 4. 数据模型

全部在 PostgreSQL。Qdrant 只存向量和块的编号，可以随时重建。

### 4.1 接入方和知识库

| 表 | 存什么 | 主要字段 |
|---|---|---|
| `tenants` | 接入方 | 名字、密钥的哈希、设置（名称、限额、联系方式从哪取） |
| `knowledge_bases` | 知识库 | 属于哪个接入方、名字、资料来源的配置、在用的索引版本 |
| `documents` | 文档原件 | 来源里的编号、标题、链接、语言、正文、内容指纹、状态 |
| `sources` | 资料来源 | 属于哪个知识库、类型（接口同步 / 上传 / 手写问答）、配置 |
| `source_files` | 上传的原文件 | 文件名、类型、大小、内容哈希、磁盘路径、状态（待解析 / 待确认 / 已确认 / 失败） |
| `parse_results` | 解析结果 | 文件、解析器和版本、Markdown、人工修改后的 Markdown、检查项和警告 |
| `ingest_jobs` | 导入和建索引任务 | 类型、目标索引版本、状态、五步各自的进度、错误、开始和结束时间 |
| `sync_runs` | 每次同步的结果 | 新增、更新、删除各几篇，出错信息 |
| `index_versions` | 索引版本 | 切块设置、向量模型和维数、关键词做法、状态、对应的 Qdrant 集合名 |
| `chunks` | 块 | 属于哪个索引版本和文档、序号、标题路径、正文、字数 |

**索引版本**：一个知识库可以有多个，各自一套切块和模型，并存，其中一个「在用」。换切块或换模型是新建一个版本，评测分数好再切过去。每个版本对应 Qdrant 里一个独立的集合。

### 4.2 对话

| 表 | 存什么 | 主要字段 |
|---|---|---|
| `conversations` | 会话 | 接入方、渠道、访客编号、语言、状态 |
| `messages` | 消息 | 谁说的（买家、AI、员工、系统）、正文、出处、买家的反馈 |
| `tool_calls` | 模型调了哪些工具 | 工具名、参数、结果摘要、耗时 |
| `retrieval_traces` | 每次检索的全过程 | 问题、用的设置、每一步的结果（见 §6.4）、耗时 |
| `handoffs` | 转人工 | 类别（工单 / 记录）、工单号、邮箱、摘要、状态 |
| `usage_daily` | 每天的花费 | 接入方、日期、调用次数、用量 |

`messages.谁说的` 里先留好「员工」，以后做实时接管不用改表。聊天记录和检索过程 90 天后清掉；入库前把像卡密、密码的内容打码。

### 4.3 评测

| 表 | 存什么 |
|---|---|
| `eval_runs` | 每次评测：用的题集版本、索引版本、链路设置、各项分数 |
| `eval_results` | 每道题的结果：检索到什么、答了什么、各项得分 |

题目本身是 `evals/` 下的文本文件，进版本管理，不放数据库。

## 5. 接口

### 5.1 接入方后端调客服服务

鉴权：请求头带接入方密钥。

| 接口 | 做什么 |
|---|---|
| `POST /v1/conversations` | 开一个会话 |
| `POST /v1/conversations/{id}/messages` | 发一条消息，回答按字流回（SSE）。请求里带访客令牌 |
| `GET /v1/conversations/{id}` | 取历史消息和转人工结果 |
| `POST /v1/conversations/{id}/messages/{mid}/feedback` | 有用 / 没用 |
| `POST /v1/conversations/{id}/handoff` | 买家点了「转人工」，带访客令牌，可带邮箱；没订单又没邮箱时回 `needs_email` |

流回来的事件：`user`（买家的话，打码后）、`status`（在调哪个工具）、`text`、`clear`（撤掉已流出的文字）、`handoff`、`done`（含出处）、`error`。服务端只给工具名和错误码，文案由聊天窗按语言出。不收语言参数：模型按买家用的语言回答。

### 5.2 客服服务调接入方

接入方后端提供一组专用接口，单独一份接口文档。鉴权：服务密钥，加上访客令牌。

| 接口 | 做什么 | 要访客令牌 |
|---|---|---|
| `GET /shop-api/articles` | 全部帮助文章：编号、语言、标题、分类、Markdown 正文。同一篇各语言编号相同；客服服务按编号同步，出处也按它链回帮助页 | 否 |
| `GET /shop-api/products?q=` | 查商品：名称、价格、库存、交付方式 | 否 |
| `GET /shop-api/orders` | 这位访客能看的订单摘要：状态、到账、交付、质保到期日（`warranty_until`，`YYYY-MM-DD`，客服服务按它算还剩几天）、在办工单；不含卡密、邮箱、付款账号 | 是 |
| `POST /shop-api/orders/{order_no}/tickets` | 给一张订单建工单，打不开的订单回 403 | 是 |
| `GET /shop-api/settings` | 店名、联系方式、回复时限；现在是否在线（接入方按自己的营业时间算）、不在线时的离开说明 | 否 |
| `POST /shop-api/notifications` | 请接入方提醒店主：`kind` 是 `handoff`（一条没挂在订单上的转人工：买家留了邮箱，或会员说不清哪一单）或 `daily_limit`（今天的用量到上限了）。转人工通知失败时标成 `unnotified`，后台能重新通知 | 否 |

鉴权：请求头 `X-Api-Key`，访客令牌放 `X-Visitor-Token`。没带或失效的令牌按游客算。

**访客令牌**：接入方后端在转发对话时签发，短期有效，代表「这个浏览器、这个会员」。客服服务只把它原样带回，不解读；能看哪些订单由接入方判断。模型看不到令牌，工具参数里也没有「是谁」这一项。

实现阶段这组接口由模拟店铺后端提供（§0）。接真实接入方时，由接入方照这份接口实现。

### 5.3 管理后台调客服服务

数据集、文档、块、索引版本的查看和操作；上传文件、解析预览、修改和确认；切块预览；任务的查看、重试和取消；检索测试；评测的发起和结果。后台自己的登录第一版用一个固定的管理员账号加密码，线上再挡一层访问控制。

### 5.4 聊天窗调接入方

聊天窗不连客服服务，只连接入方自己的域名，接入方照下面这组接口转发（模拟店铺的 `demo_shop/relay.py` 是参考实现）。接入方在转发时加上服务密钥、签发访客令牌，并记住会话归哪个浏览器。

| 接口 | 转给客服服务的 |
|---|---|
| `GET {base}/config` | 问一下 `GET /v1/status`：开关、单条消息最多几个字、常见问题（按语言，在客服后台「接入方」页改）。再加上接入方自己的店名、联系方式、回复时限、整页版地址、出处链接模板、主题色（可不给，默认蓝色） |
| `POST {base}/conversations` | `POST /v1/conversations`，访客编号由接入方定 |
| `GET {base}/conversations/{id}` | 取历史；不是这个浏览器的会话回 404，聊天窗就开新的。转人工期间聊天窗每 5 秒带着 `after`（已有的最后一条消息编号）来拉客服的新回复，接入方原样带上这个参数（人工接管，docs/07） |
| `POST {base}/conversations/{id}/messages` | 加上访客令牌，SSE 原样转回 |
| `POST {base}/conversations/{id}/images` | 发一张图片（multipart，字段 `file`），加上访客令牌（表单字段 `visitor_token`），SSE 原样转回（docs/09） |
| `GET {base}/conversations/{id}/images/{image_id}` | 看这个会话里的图；不是这个浏览器的会话回 404 |
| `POST {base}/conversations/{id}/handoff` | 加上访客令牌 |
| `POST {base}/conversations/{id}/messages/{mid}/feedback` | 原样 |

嵌入：`<script src=".../widget.js" data-base="/api/chat" data-mode="float">` 自动挂悬浮窗；或 `CustomerAgent.mount({ mode: "page", target, lang })` 挂整页版。语言取参数，没有就看页面的 `lang`。

`widget.js` 文件名不变，接入方发它时带 `Cache-Control: no-cache` 和 `ETag`：浏览器每次先问一下有没有变，没变回 304，变了马上用新的。不要设长缓存，否则更新后买家还在用旧的聊天窗。

## 6. 检索链路

### 6.0 导入流水线

```
接口同步 ─────────────────┐
上传文件 → 解析 → 人工确认 ─┼→ 清洗 → 切块 → 算向量 → 写入 Qdrant → 索引版本
手写问答对 ───────────────┘
```

- **解析器接口**：输入文件，输出 Markdown、检查项和警告。每种文件列出能用的解析器，第一个是默认：文本类用自带，Word 和 HTML 用 Docling，PDF 默认 Docling、可换成「只取文字」（快，不认表格，docs/05 §32）。导入页可以换解析器重新解析。以后加 MinerU 不动别的代码。
- **任务**：放在 PostgreSQL 的 `ingest_jobs` 里，由服务内一个后台工作进程按顺序取，同一时间只跑一个算向量的任务，避免挤爆显存。每步可重试，重启后能接着跑。
- **解析在单独的子进程里跑**，带超时和内存限制。上传的文件不可信，解析器崩了也不影响对话服务。
- **切块预览**：切块实验室调用同一套切块代码，只算不写库，保证预览和正式结果一致。
- **长度单位**：块大小同时显示字数和 token；限制以向量模型的 token 为准。
- **原文件**放在磁盘目录，不放数据库；线上挂到容器卷并纳入备份。
- **向量地图**：第一版直接用 Qdrant 自带面板，要挡在访问控制后面，不对外开放。

### 6.1 入库

1. **同步**：定时（默认 10 分钟）从接入方拉全量列表，比内容指纹。变了的整篇删掉重做，下架的删掉。
2. **清洗**：Markdown 保留标题层级，去掉纯装饰的内容。
3. **切块**：第一版按标题分段，过长的再按字数切；每块带上「文章标题 › 小节标题」。块的大小、重叠是索引版本的设置。
4. **算向量并写入**：块的原文进 `chunks`，向量进 Qdrant。

以后拿评测对比的切块做法：父子分段（小块检索、大块给模型）、给每块加一句上下文说明（Anthropic 的 Contextual Retrieval 做法）。

### 6.2 查询

一串可开关的步骤：

| 步 | 做什么 | 第一版 |
|---|---|---|
| 改写 | 结合上文把问题补全 | 关 |
| 语义检索 | 问题算向量，在 Qdrant 里搜 | 开，取前 20 |
| 关键词检索 | Qdrant 自带的关键词搜索 | 开，取前 20 |
| 融合 | 把几路结果合成一个排名（RRF） | 开 |
| 重排 | 重排模型重新打分 | 关（本机评测时开） |
| 截取 | 取前几块交给模型 | 前 5 |

关键词检索的另外两种做法（bge-m3 的关键词向量、Python 里 jieba 分词算 BM25）做成可替换的。Qdrant 中文分词的实际效果是「待实测」。

### 6.3 基线

「整库放进提示词」做成链路的一种：不检索，把知识库全部正文交给模型。所有做法都和它用同一批题比。

### 6.4 检索过程的记录

每次检索存一份，测试台和评测页显示的就是它：

```
问题原文、改写后的问题
用的索引版本、每一步的开关和参数
每一路：找到的块（编号、分数、排名）、耗时
融合后的排名
重排前后的排名和分数
最后交给模型的块
总耗时
```

## 7. 对话

### 7.1 循环

模型自己决定调哪个工具，每轮最多调三次。

| 工具 | 做什么 |
|---|---|
| 搜资料 | 走 §6.2 的检索链路，返回几块正文和出处 |
| 查商品 | 调接入方接口：价格、库存、规格 |
| 查我的订单 | 调接入方接口，带访客令牌 |
| 转人工 | 建工单或转人工记录，返回给买家看的说明 |

工具是每个接入方的连接器提供的，「搜资料」和「转人工」是通用的。

### 7.2 提示词怎么组成

固定部分（通用规矩、接入方的名称和用语规矩、工具说明）放前面，利用提示词缓存；后面是这次对话的历史。规矩的原文见产品需求 §5.5。

### 7.3 代码里把关的

不全靠提示词，下面这些由代码保证：

- 话题和长度限额、每轮工具次数上限。
- 工具返回里不会有卡密（接入方接口就不给）。
- 入库前打码。
- 转人工由工具完成，模型说「已转人工」但没调工具的，按没转处理并补转。
- 模型回答里出现承诺类的说法（「可以退款」「会补发」），评测里专门出题查；上线后抽查。

### 7.4 模型

日常问题用小模型，难的升级到大模型。怎么判断「难」、两档各用哪个型号，等第 3 期有了真实对话的用量再定。每天花费上限也在那时算。

## 8. 评测

### 8.1 题目格式

每道题：问题、属于哪一类（照资料能答 / 要查的 / 该转人工 / 刁钻题）、应该找到哪些文档、参考答案、期望的行为（回答 / 转人工 / 拒绝）。

### 8.2 两层分数

| 层 | 量什么 | 怎么算 |
|---|---|---|
| 检索 | 该找到的文档在不在前 k 块里、排第几 | 代码直接算，不用模型 |
| 回答 | 是否只说了资料里有的、是否答对、行为对不对 | 模型打分；行为类的（有没有调转人工）代码直接查 |

### 8.3 两个知识库

| 知识库 | 用途 |
|---|---|
| 接入方的帮助文章和商品介绍 | 真正上线用的；量大概很小，「待实测」 |
| 一份私有的中文项目文档集（14 篇，不随仓库发布） | 练习用：长文，有表格和流程图，体现得出各种做法的差别 |

可以再加一份公开的中文检索数据集（自带标准答案），具体选哪份第 0 期查。

## 10. 安全清单

1. 客服服务只在内网可达；对外只有接入方的转发接口。
2. 访客身份只由接入方后端确定（§5.2）。
3. 卡密不经过客服服务：接入方接口不返回。
4. 买家的话、资料正文、接口返回都当数据；规矩只来自提示词的固定部分。
5. 资料同步只读接入方的公开内容；知识库里不放内部文档（练习知识库只在本机用，不接到线上的聊天窗）。
6. 密钥放环境变量，不进代码和前端。
7. 限额和总开关（产品需求 §5.8）。
8. 聊天记录打码、90 天清理。
9. 上传文件校验类型和大小，文件名不进路径，解析在隔离的子进程里跑，带超时。文件内容当数据，里面的指令不执行。
10. Qdrant 和它的面板不对公网开放。
11. 管理后台要登录：一个管理员账号，密码走环境变量；登录 cookie 只走 HTTPS、不给脚本读、不跨站发送，签名钥匙由密码经 scrypt 派生；猜错太多次暂停登录。
12. 服务不公开接口列表（不开 /docs 和 /openapi.json）。
